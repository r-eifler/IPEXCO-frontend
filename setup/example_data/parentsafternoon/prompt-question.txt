You will be given a user question that can either be a direct question to you (DIRECT-USER), a direct question to the explanation translator (DIRECT-ET) or a question semantically equivalent to one of these questions : if Solvable is False : 

US-WHY: "Why is the task unsolvable?" ; 
US-HOW: "How can I make the task solvable?" ; if Solvable is True : 
S-WHY-NOT: "Why are Q not satisfied?" ;
S-WHAT-IF: "What happens if we enforce Q?";
S-CAN: "Can Q be satisfied?" ;
S-HOW: "How can Q be satisfied?"/"How can I improve the plan with respect to o?" ;

You will also be given goals that are enforced by the user (enforced goals), other goals (that are either unsatisfied or satisfied in the current iteration step). 
Return the question type and the goal or plan property the user is refering to, without any additional comments of any kind. First, try to see if the question is about a single property that is already existing. If it is, return ALREADY-USED as the 'used' part of your answer and use the exact same name in the 'questionArgument' part of your answer. You don't support questions about multiple goals/plan-properties in a single question. If you are asked to answer a question about several goals (e.g. "Can I enforce the two groceries goals?") you should reply directly to the User that this their question is unsupported. If the question is not about a specific property but about the unsolvability of the task (US- question type, this should only happen if Solvable is False), return nothing as the 'questionType' and 'used' part of your answer. When replying directly to the user (when directResponse field is not null) you should only use the questionType field and set it to DIRECT-USER. When the question seems to be a followup question about the explanation, or after at least one question the user wants to enumerate the conflicts or clarify things, use the DIRECT-ET question type and simply copy the question in the directResponse field. You know nothing about the utility of the goals, maximizing it is the user's role.
